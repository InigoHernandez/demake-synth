# Demake on the M-VAVE FM-1

The FM-1 build: Demake's core (`firmware/src`, the same code the browser and the host run) on the open FM-1
platform. `dmk_fm1.c` is Demake's glue; everything else here is the platform, taken as MONO2K carries it (CS-1's,
which stands on Dinghy, SLOOP and Felucca), with the few changes listed below.

## Build

```bash
.venv/bin/python tools/fm1/build.py            # build/fm1/demake.fwsc, identity FM-1_965
.venv/bin/python tools/fm1/build.py --diag     # build/fm1/demake-test.fwsc: a load meter along the screen's top
.venv/bin/python tools/fm1/build.py --bench    # build/fm1/demake-bench.fwsc: the meter and a known load on K1
```

It needs JieLi's Linux toolchain (clang 4.0.1 for pi32v2) in `~/.jieli/toolchain` (`JIELI_TOOLCHAIN`), the JieLi
AC79 SDK (`AC79NN_SDK_V1.2.1_2023-12-13`) in `~/fw-AC79_AIoT_SDK` (`AC79_SDK`; three of its files go into the
package) and, on a Mac, a container runtime that runs linux/amd64 (colima with Rosetta: `colima start --vm-type vz
--vz-rosetta`; `DOCKER_CONFIG` defaults to `~/.jieli/docker`).

The build checks what Felucca's, CS-1's and MONO2K's check: the entry at the XIP address, no code in RAM calling out
of it, no reference to the chip's ROM, no float or 64-bit division helper (the build links no libgcc), and the sizes:
the image within the app slot (581 KB), `.data + .bss` within 96 KiB, the pool within 336 KiB.

**Never publish a package that has not run on an FM-1.**

## How it runs

- The core runs in the main loop alone, as it runs in the browser's worklet. The loop renders the sound ahead into a
  ring (six blocks of 128 frames, 17 ms) and the audio interrupt only copies it out, so no interrupt lands inside an
  edit. A pass renders at most half the ring, so a core slower than the sound stutters but never starves the panel
  or the watchdog.
- The screen: the core's 4-bit frame (16 colours), through the theme's 16-entry RGB565 table, sent in 8-line strips
  where it changed, one strip a pass while the audio renders (a whole screen is 77 ms of SPI at 12 MHz).
- The panel: the platform's buttons, encoders and 27 keys mapped onto the core's (`dmk.h`); the LEDs on from a
  quarter of the core's brightness (the FM-1's are on or off). MASTER is the platform's output level.
- MIDI in: USB-MIDI and the TRS jack, into `dmk_midi`.
- The update entry, the USB rescue (hold OCT− at power-on) and the boot guard (two failed boots: the rescue) are the
  platform's: an installer reaches the FM-1 whatever the app does.

## Changed from the platform (MONO2K's changes, kept)

- `hal/fm1_lcd_hw.h` `fm1_lcd_done`, `src/lcd.c` `lcd_idle`: a transfer's end without waiting for it.
- `src/platform.c`: `BANK_AT` / `BANK_LEN` and `CV_MAX` can be set by the app; an app's SysEx hook (`APP_SYSEX`)
  sees each frame before the update entry does. Demake's: the app may draw the update's screen (`APP_OTA_SHOW`) and
  refresh it while the update waits (`APP_OTA_IDLE`); the rescue mode keeps the platform's own.
- `src/sense.c`: its tables from `gen/sense_tables.h` (generated by `tools/fm1/gen_sense.py`) in place of CS-1's.
